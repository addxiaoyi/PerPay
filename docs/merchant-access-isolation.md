# StarPAY 商户与管理员隔离

普通商户只可访问主站授予的 owner/member 商户。服务器逐一校验目录，不先将
全部商户发送到浏览器。前端隐藏管理功能，后端独立拒绝越权请求。

## 边界

- `/api/merchant/epay/access` 返回当前主体及已授权商户，拒绝混杂主体或角色。
- 每次业务请求重新通过主站 `/api/merchant/access` 鉴权，并核对本地绑定；
  `merchantId`、`scope`、`targetMerchantId` 和角色请求头不能代替授权。
- 全站记录、运行状态、成员管理及管理员审计要求管理员身份；余额、费率、
  退款和提现审批同时要求同源与 CSRF 检查。
- 关联主站的实例中，旧 `/api/admin/v1/*` 会话也须通过当前主站管理员检查。
  主站降权后，保留的独立管理 Cookie 不会继续授予管理访问。
- 恢复缓存页面、切回标签、重新联网及权限刷新期间隐藏旧界面；身份范围变化
  时取消旧请求、清理商户缓存，再渲染新范围。

## 回归

`npm run test:permissions` 包含 owner/member 跨商户读取、全站查询、伪造管理
请求与旧会话降权测试。拒绝写入后完整比较订单、期初余额、账本、回调和审计
记录，确保拒绝访问同时不产生财务副作用。

`npx playwright test ui-tests/portal-permissions.spec.ts --project core --workers=2`
覆盖 390px/1280px 导航、其他商户 URL、直接进入管理端及缓存恢复期间清除旧
管理员内容。两项命令均接入 CI；完整检查另包含费率事务、账户与成员操作回归。

所有权限测试使用隔离身份和合成记录，不借用真实商户会话。主站个人中心核对
来源、所有者与成员的操作区别见 [权限说明](profile-permissions.md)。
