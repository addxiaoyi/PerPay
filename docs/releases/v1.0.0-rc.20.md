# StarPAY 1.0.0-rc.20

Receiving websites can reach the public balance order, query and refund APIs through explicit PerPay proxy routes. Maintenance rendering preserves these routes and pauses new order/refund writes. API onboarding and Wiki now explain PID/key HMAC authentication, original-body callbacks, idempotent fulfillment, queries, refunds and error handling, with copyable examples.

The browser integration lab creates and verifies demo signatures using a public test key entirely locally. The downloadable SDK includes a transport-isolated self-test for create/query/callback/replay/refund behavior. It sends no network requests and spends no real money. An optional callbackKey verifies old-order callbacks after rotation while current key credentials authenticate queries.

An insufficient wallet links to recharge with the original checkout and payer. The recharge form computes the shortfall from server-verified balances, preserves the original signed checkout in its payment return URL, and offers a return link after funding. Checkout expiry remains 20 minutes, and the original order still requires explicit payment confirmation. Arbitrary continuation destinations are rejected.

Schema stays 74, with no migration or ledger rewrite. Real invoices and automatic invoice sync stay off. Preserve a verified database backup and `PERPAY_MASTER_KEY`; follow [fixed-version rollback](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.20/docs/maintenance.md#固定版本与回滚). Never discard financial records created after deployment. The intended container tag `ghcr.io/mashiro0619/perpay:1.0.0-rc.20` has not been published.
