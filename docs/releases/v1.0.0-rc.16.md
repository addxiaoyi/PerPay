# StarPAY 1.0.0-rc.16

Unpublished source candidate. The intended image tag `ghcr.io/mashiro0619/perpay:1.0.0-rc.16` has not been published.

Platform fee invoicing now uses the confirmed payment's recorded fee as its gross invoice amount and the merchant's saved buyer identity. It never invoices the customer's full payment or recalculates old fees from the current merchant rate. A separate fee request table preserves seller/buyer/tax snapshots and one application per payment; the customer invoicing records remain separate.

Owners can prepare their invoice title, tax ID and email while execution is off. Automatic issuance requires the global issuance gate, automatic synchronization, an enabled and unexpired platform fee profile, and the merchant's saved auto-invoice preference. Pending payments, zero fees, missing buyers, self invoices and payments with active/successful refunds are excluded. An uncertain submission is never automatically replayed. Existing reconciliation and file-query flows support fee invoices, and invoice-number uniqueness spans customer and fee receipts.

Migration 72 adds three fee invoice tables and their guards; migrations 69–71 are unchanged. Refunds against an active fee invoice require reconciliation/red cancellation. This version does not automatically red-cancel externally reversed invoices. Failed or untraceable submissions require operator investigation before another invoice can be attempted.

The prepared Shanghai platform profile uses ordinary electronic invoices, a 1% rate and a policy deadline at the end of 2027 for the declared platform technical service. The actual service must match the classification. This is a closed configuration, not proof that the provider has accepted a real invoice. No recharge, real issuance or email delivery was performed.

Runtime compatibility is schema 24–72. Back up the database and `PERPAY_MASTER_KEY` before upgrading; rollback to rc.14 requires its schema-70 backup and matching key. See [fixed-version rollback](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.16/docs/maintenance.md#固定版本与回滚) and [migration recovery](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.16/docs/maintenance.md#数据库迁移备份与恢复).
