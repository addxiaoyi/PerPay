# PerPay 1.0.0-rc.6

Restore merchant settlement requests and administrator payout recording in the
PerPay workspace. Requests atomically freeze available balance and are retried
with the original request ID. Administrators record an independently completed
payout with its reference or reject the application and release the hold. This
workflow does not initiate a bank transfer. Historical settlement records remain
readable with their original owner.

Schema 62 adds immutable native settlement identities and guarded terminal
decisions. Balance, ledger, settlement and audit writes share one transaction.
Current StarMC identity, merchant binding and CSRF checks authorize every write;
ordinary merchants cannot mark a settlement paid. The financial monitor also
checks settlement postings.

Before upgrading a live instance, pause new admission, drain service writes,
capture and verify a backup with the original `PERPAY_MASTER_KEY`, then upgrade
in an independent data copy. Keep the schema-61 source copy. After schema 62
accepts financial writes, rollback must preserve those writes and callback
ownership; do not switch an old database back over the current one.

The planned image is `ghcr.io/mashiro0619/perpay:1.0.0-rc.6`; this file does not
claim publication. See the [fixed-version recovery procedure](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.6/docs/maintenance.md#固定版本与回滚).
