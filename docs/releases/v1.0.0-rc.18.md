# StarPAY 1.0.0-rc.18

Unpublished source candidate. The intended tag `ghcr.io/mashiro0619/perpay:1.0.0-rc.18` has not been published.

Registered receiving websites can adapt merchant balance payments with their existing PID/key or main API credentials. Signed server-side order creation returns a StarPAY checkout URL. The payer must log in, select an owned merchant wallet and explicitly confirm the debit with same-origin CSRF. Creation, visits, signatures or callback URLs alone cannot spend another merchant's funds. Payment atomically debits the payer, credits the receiver net of the snapshotted fee, records confirmation and enqueues a signed JSON callback. Duplicate confirmation never debits twice. Full refunds return to the original payer and require sufficient receiver net proceeds; active invoices must first be reconciled/red-cancelled. No partial refund or separate refund webhook is provided in this release.

Invoice annual service costs 100 yuan for 365 days, deducted from verified available merchant balance only on an explicit purchase/renewal. Early renewal extends remaining service time; idempotency and expected balance/expiry state prevent duplicate charges. It does not auto-renew. The platform does not collect the fee while invoice execution or provider authorization is unavailable. A paid annual subscription is a per-merchant prerequisite for new fee invoices, not a platform activation prerequisite. Buyer preparation remains available independently.

Migration 73 adds wallet payment/refund and annual subscription tables, extends fee invoice payment types without altering migration 72, and preserves previous invoice receipts and ledger records. Balance confirmations and subscription charges are included in financial audits. Runtime compatibility is schema 24–73; rc.17 cannot open schema 73. Preserve the verified database backup and `PERPAY_MASTER_KEY` before deployment. After new financial records exist, never restore the pre-deployment backup merely to roll back code. See [fixed-version rollback](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.18/docs/maintenance.md#固定版本与回滚) and [migration recovery](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.18/docs/maintenance.md#数据库迁移备份与恢复).

Website adaptation is documented in the balance-payment guide and typed Node SDK. Invoice execution remains closed pending the operator's vendor renewal/authorization. Development and deployment validation use synthetic funds; no real balance payment, annual charge or invoice is created by the tests.
