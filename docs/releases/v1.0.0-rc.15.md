# StarPAY 1.0.0-rc.15

Unpublished source candidate. The intended image tag `ghcr.io/mashiro0619/perpay:1.0.0-rc.15` has not been published.

Administrators can preview and confirm an original fa-piao invoice number for an unresolved application. Preview checks the immutable seller/buyer/amount/tax snapshot without issuing an invoice or saving a receipt. Confirmation repeats verification and atomically saves the receipt, invoice status and operator audit. The operator must confirm the original application association and valid, unreversed blue invoice against provider evidence; the public details API does not prove the application association or external red cancellation status.

Review tokens expire after five minutes and bind the actor, merchant, current application snapshot, candidate number and evidence reference. Changed, terminal, replayed and conflicting reviews are rejected. Migration 71 adds a unique receipt invoice-number index; existing duplicate receipts cause migration to fail rather than silently reassign invoices. Migrations 69 and 70 are unchanged.

Real issuance and automatic synchronization remain disabled. Reconciliation only reads provider invoice details; it can fail while the vendor service is expired and will then save nothing. No recharge or real invoice was used for validation.

Database compatibility is schema 24–71. Back up the database and `PERPAY_MASTER_KEY` before upgrading. Returning to rc.14 requires restoring its schema-70 backup together with its matching key; an rc.14 binary cannot open schema 71. See the [fixed-version rollback guide](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.15/docs/maintenance.md#固定版本与回滚), [migration recovery guide](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.15/docs/maintenance.md#数据库迁移备份与恢复) and [fa-piao recovery guide](https://github.com/Mashiro0619/PerPay/blob/main/docs/fa-piao-invoices.md).
