# StarPAY 1.0.0-rc.22

Merchant callback outages now retain automatic retries for at least 72 hours under normal scheduling, with exponential backoff from 30 seconds up to one hour and a bounded 80-attempt budget. Retry deadlines remain in the database across restarts. Unsupported POST formats still switch to the existing signed GET fallback after three attempts; unrecoverable failures remain visible for manual retry.

Payment recovery runs up to three official queries concurrently and processes up to 20 orders per pass. A malformed query record is reported and left for investigation while other orders continue recovering. Provider signatures, account identity, exact amounts, leases and transactional payment/ledger/outbox checks remain mandatory.

The HTTP listener opens before recovery workers drain backlog, allowing provider notifications to arrive during startup. A transient callback worker startup failure retains its scheduled retry. Shared-source synchronization retries fresh captures twice within a bounded cycle without relaxing the 90-second freshness gate or snapshot authentication checks.

Schema remains 74. This release does not enable invoice issuance or introduce test financial transactions. Operational callback monitoring separates an overdue retry from a merchant outage that is waiting for its scheduled retry; both remain visible.

The intended image tag is `ghcr.io/mashiro0619/perpay:1.0.0-rc.22`; no container publication is claimed by the server deployment. Retain the database backup and `PERPAY_MASTER_KEY`. See [fixed-version recovery](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.22/docs/maintenance.md#固定版本与回滚) before switching or restoring a release.

Server deployment was verified on 2026-11-24. Schema 74 and the current database were retained; 156 business tables matched across maintenance startup. Nine public health probes passed and 124 confirmed payments had 124 delivered merchant callbacks, with no inconsistent ledger records. The pre-existing aged-order alert and intermittent shared-host source synchronization failures remain visible. No real financial transaction was created for testing.
