# StarPAY 1.0.0-rc.19

Merchant balance recharge now uses the existing Alipay web and WeChat native payment adapters. Owner/admin confirmation, distinct CSRF and immutable recharge markers separate recharge from sales orders. Verified exact payment evidence credits the full principal once with zero merchant transaction fee. Recharge generates no external goods callback and cannot be used as sales invoice principal.

Configured platforms can sell the 100-yuan/365-day invoice annual service before real invoice issuance opens. The owner/admin must explicitly acknowledge the purchase-date term and delayed issuance. Purchasing does not activate invoice execution; live issuance purchases still probe authorization. Existing idempotency, balance-version and expiry checks remain.

Merchant and administrator sidebars include a searchable feature Wiki, with balance payment setup, typed Node SDK download, callback verification, refunds, annual service and invoice recovery. Merchant sidebars also include balance recharge.

Migration 74 adds immutable recharge markers without changing existing orders or ledger records. rc.18 cannot open schema 74. Preserve a verified backup and master key; once new financial records exist, do not restore an old database to roll back code. Build, financial tests and isolated backup/restore rehearsal are required before deployment. Real invoice and automatic sync gates remain off. No real payment or deduction is used for verification.

Preserve `PERPAY_MASTER_KEY` and follow [fixed-version rollback](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.19/docs/maintenance.md#固定版本与回滚) for recovery. This is a local production release; the intended `ghcr.io/mashiro0619/perpay:1.0.0-rc.19` container tag has not been published.
