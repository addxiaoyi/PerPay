# StarPAY 1.0.0-rc.10

Restore authenticated EPay merchant balance queries and manual callback retry
requests. Retrying a failed callback keeps every prior attempt and continues
monotonic attempt numbers; schema 66 stores the new retry budget and immutable
retry requests. In-flight and cross-merchant requests are rejected. The merchant
workspace exposes retry only for a failed native callback, and queued does not
mean delivered.

EPay `api.php?act=refund` accepts a native-order refund application under the
merchant key. It uses a stable retry identity and explicitly reports that the
application awaits administrator review. It does not return the old misleading
"refund succeeded" response before channel confirmation. Historical refunds and
callbacks retain the legacy owner. No test invokes real callback or refund
transports.
