# PerPay 1.0.0-rc.4

## Changes

- Add persistent, expiring, scope-specific order, receipt, and invoice access grants for native StarMC orders.
- Add StarMC order lookup and receipt routes and keep the existing loopback-owned order capability routes available for historical orders.
- Add an invoice application path that requires a verified payment, checks available balance, records the application and service fee in one transaction, and safely handles retries.
- Extend schema compatibility to version 60.

## Validation

- Node 24 regression, financial rollback rehearsal, migration checks, TypeScript checks, and server build must pass before deployment.
- Invoice application and receipt paths have automated isolated tests; no real payment or invoice provider call is made by those tests.

## Limitations

- This candidate does not enable production order admission or callback delivery. Channel and finance acceptance gates still apply.
- The invoice application fee must be explicitly configured with `PERPAY_EPAY_INVOICE_FEE_CENTS`; issuance still depends on the configured invoice operations workflow.

## Upgrade and recovery

Back up the database and verify the original `PERPAY_MASTER_KEY` before upgrading. Stop the application and backup writer during the upgrade, and keep `app`, `backup`, and `maintenance` on the same build. A database migrated to schema 60 must not be opened by an older build; rollback requires restoring the verified pre-upgrade database and its original master key.

The image reference for this unpublished candidate is `ghcr.io/mashiro0619/perpay:1.0.0-rc.4`. Publishing this file or building the image does not authorize production deployment or traffic cutover. Follow the fixed-version rollback procedure in the [maintenance guide](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.4/docs/maintenance.md#固定版本与回滚).

```sh
docker compose stop app backup
```
