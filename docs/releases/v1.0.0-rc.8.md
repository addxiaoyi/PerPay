# PerPay 1.0.0-rc.8

Administrators can create a merchant for an existing StarMC account from PerPay.
A persistent request fixes the requested owner, display name and callback URL
before main-site creation. The enrollment accepts only the matching newly
created identity, rechecks administrator permission after the network wait, and
atomically creates the PerPay merchant, channel bindings, encrypted key, zero
opening balance and audit event. A lost main-site response can be retried with
the same request; unrelated historical identities are not automatically adopted.

Schema 64 adds creation requests and immutable enrollment evidence. Legacy source
synchronization accepts a new main merchant only when its exact owner and API ID
match a completed enrollment. Existing historical orders, keys and liabilities
are untouched. Native orders and financial postings remain owned by PerPay.
