# PerPay 1.0.0-rc.9

Restore the configured Alipay website-payment flow alongside QR collection.
Existing EPay merchant URLs use the configured PC/WAP product for new orders;
existing QR submissions retain their original flow. The StarMC order API and
merchant collection form accept `alipay_web` without changing the merchant's
amount, callback protocol or unique trade identity.

Schema 65 stores immutable web-payment product choices and encrypted signed
links. Links target the fixed official Alipay gateway with RSA2, pinned recipient
identity and the configured certificate serials. Browser returns are scoped
capabilities and only poll local verified payment state; URL parameters never
authorize accounting. Signed channel callbacks and official trade queries use
the existing atomic payment, ledger and callback transaction.

Production inspection found 184 historical main-site `alipay_web` orders and
Alipay product `pc` enabled. WeChat Native is enabled; H5, JSAPI and miniprogram
remain unconfigured/disabled and are not silently enabled by this release.
Automated validation never opens a real payment link or sends a real refund.

Preserve the database and original `PERPAY_MASTER_KEY` before migrating schema
64 to 65, rehearse both upgrade and prior-release restoration, then upgrade with
new admission paused. After new financial writes, retain the upgraded database
during rollback. Planned image `ghcr.io/mashiro0619/perpay:1.0.0-rc.9` is not a
publication claim. See the [recovery procedure](https://github.com/Mashiro0619/PerPay/blob/v1.0.0-rc.9/docs/maintenance.md#固定版本与回滚).
