# StarPAY 1.0.0-rc.25

Payment operations now retain alert deliveries across restarts and send failure and recovery notifications through a configured SMTP or HTTPS endpoint. Financial auditing stays network isolated. A separate sender retries delivery with a persistent lease and backoff. Historical unpaid orders remain visible as a separate finding.

If financial auditing stops, the sender queues an `audit_unavailable` notification without refreshing the audit evidence or heartbeat. A full delivery queue is drained before that notification is added, preserving existing events and allowing the monitor failure to be reported.

The read-only invoice preflight checks provider authorization and seller configuration without issuing invoices or changing the database. Its scheduled report can feed the payment alerts. An expired provider service, SMS or face verification requirement keeps issuance blocked; a successful diagnostic does not enable issuance.

Source synchronization records bounded stage timings and safe error categories. Release tooling derives its registry target from the owning repository so a fork cannot publish into the upstream registry by accident. Python operations checks run alongside the existing payment and recovery checks.

The separate [StarMC durability integration](https://github.com/addxiaoyi/PerPay/blob/v1.0.0-rc.25/integration/starmc/README.md) includes the attested main-site overlay, its minimum fixture support, and reproducible crash/replay tests. CI verifies it with `npm run test:starmc`. Deploying PerPay does not install the main-site overlay.

Schema 74 is unchanged. Preserve the active database, original master key and callback queues. Backups to another machine are deferred at the operator's request. Real merchant fulfilment must be validated against that merchant's receiving application; an SDK test does not establish fulfilment.

The intended fork image is `ghcr.io/addxiaoyi/perpay:1.0.0-rc.25`. Preserve `PERPAY_MASTER_KEY` and use the [fixed-version recovery guide](https://github.com/addxiaoyi/PerPay/blob/v1.0.0-rc.25/docs/maintenance.md#固定版本与回滚). Source preparation and an image name do not establish that a tag has been published.
