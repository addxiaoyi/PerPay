# 商户自动提现候选

目标是 StarPAY 向商户的银行卡、支付宝或微信零钱打款。公户开户银行为中国银行，
银行出款服务、微信商家转账和支付宝转账权限均待核实。

此分支提供开发候选，不是已开放的生产出款功能。生产启动代码没有注册任何出款
适配器，所有自动提现通道默认关闭，现有收款和线下提现结算继续使用原流程。

## 本次实现

- `/pay/merchant/payouts`：提交及查看脱敏收款账户。所有者可绑定，成员仅可查看。
- `/pay/admin/merchants/:merchantId/payouts`：查看完整资料并留下审计，审核、拒绝或停用收款账户。
- 收款人、银行账号、支付宝账号、OpenID 等完整资料用现有主密钥加密。修改收款账户
  需新增记录并重新审核，已申请提现固定原账户，不能被后来改绑替换。
- 自动提现申请与余额冻结在同一事务中提交。管理员审核记录付款方、金额、依据及
  每笔/每日限额；关闭通道或收款账户被停用时不能发出新款。
- 持久队列先记录提交占用，再调用渠道；超时与进程重启后只查询原出款单号，不换单
  重打。渠道结果须验签、金额和身份一致；只有可信终态才扣除冻结款或解冻退回。
- 自动提现与旧结算表关联，禁止把同一笔再手工登记已打款或驳回。处理中余额继续冻结。
- 管理员请求读完正文后重新验证主站权限，防止提交过程中降权后继续执行。

## 渠道完成范围

支付宝证书绑定、签名提交、原单查单已实现。2026-11-07 生产只读查单返回经签名核验的
`insufficient-isv-permissions`，没有提交转账。见 [支付宝权限清单](alipay-payout-readiness.md)。
已验证整笔退回可以返还余额一次；原付款历史保留，人工账单不会直接改变资金。

微信已实现一次性 OAuth 身份绑定、免确认收款授权、授权查询/撤销回调、授权后转账和
原单查单，均接入实际路由及商户页面。手填 OpenID 不能自动出款。隔离测试使用合成渠道
签名和浏览器桥接替身，产品权限、公众号配置与真机实际到账尚未验收。
详见 [微信授权与出款](wechat-payout-integration.md)。

中行仍需取得开户行提供的真实产品和接口规范，未虚构银行 API。
[开户行咨询资料清单](boc-direct-link-checklist.md) 可直接提供给客户经理，尚未代为发送。

日终查询、管理员报告、人工账单逐笔比较、差异留存和整笔退回已实现；自动下载渠道资金
账单及账户完整余额核对仍需实际产品权限和账单规范。见 [退回与日终核对](payout-reconciliation.md)。

## 开通前资料与验收

1. 中国银行：银企对接服务/付款产品名称、对应接口文档版本与测试接入方式；凭据通过
   本机或服务器密钥文件配置，不写入 Git，不通过聊天发送私钥。
2. 微信、支付宝：商户平台的转账产品已开通状态、已批准的真实业务场景、出资账户、
   额度与收款人授权规则。已有收款密钥不代替出款准入核验。
3. 联调使用隔离数据库和渠道测试能力，覆盖超时、重复请求、重启、撤销、失败、资金
   不足、回执不符、退回及跨商户访问。真实转账另以明确金额和收款方验收。
4. 验收后再注册适配器和定时任务，首阶段保留管理员审核。关闭新出款后仍需使用原
   付款账户查询在途单；不能切换付款账户补发同一笔。

## 测试与迁移

`npm run test:payouts` 执行账户权限、加密、冻结账务、验签、限额、原单恢复和迁移回归。
`npx playwright test ui-tests/merchant-payouts.spec.ts --project core` 使用真实隔离后端
验证手机/桌面账户绑定和管理员审核，并确认渠道关闭时不能提交自动出款。

schema 67 新增账户、队列和尝试记录；schema 68 增加微信身份/授权、退回和对账证据；历史订单、余额和结算不重写。备份需要数据库
与原主密钥。回滚不得让 schema 66/67 程序打开新库，也不得用旧备份覆盖新出款记录。
