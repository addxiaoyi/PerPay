## 权限修复

服务端逐商户重新核对主站会话、主体和本地绑定；全站数据及管理操作要求实时
管理员身份。旧独立管理会话也不能绕过主站降权。前端在恢复页面、切回标签和
重新联网时隐藏旧内容，取消旧请求并清除已失效身份的查询缓存。

主站个人中心的角色判断、服务器能力映射与资料更新白名单已用只读源码核对。
夹具随仓库保存，并校验内容摘要。完整边界见 [权限说明](profile-permissions.md)。

## 独立检出与检查

使用 Node 24.22.1，按 README 的命令安装和运行检查。权限回归不依赖生产服务、
SSH 或额外登录。CI 的 `check` 包含版本、OpenAPI、TypeScript、Node、前端单元
测试、服务器构建、显式权限回归和 npm 安全审计；`ui` 构建应用后执行 Chromium
核心回归，并保留失败截图和 trace。

历史 MySQL 恢复、旧进程提取及旧工作台浏览器测试有独立环境前提；缺少环境时
会报告跳过。它们不能替代当前商户权限回归，也不能将跳过解释为恢复验收通过。
PHP 桥接测试需要 PHP 和 SQLite 扩展。新权限检查不设凭据条件或可选跳过。

## 生产与后续验收

本次 GitHub 交接不重启服务，不修改生产余额、订单或回调。公开代码与合成测试
不包含真实数据库、支付凭据、登录会话、截图和服务器运行报告。

- 用户已要求新开票暂时关闭；历史发票仍可查询。重新开放前需真实税码和开票验收。
- 新收款的资金闭环等待用户正常交易后核对渠道状态、订单、账本和商户回调。
  二维码生成或 HTTP 成功不是收款证明。
- 未证实归属的旧订单保持原始 ID 和原处理方，不能自动归入现有商户。
- 更换主站权限实现后，重新核对源码版本及身份接口再更新契约夹具。
- 现有上游镜像发布配置保留；本分支不打版本标签，不宣称已发布 fork 镜像。

任何后续生产发布都应备份配置、应用、数据库及原主密钥，验证隔离恢复，暂停新
订单后以同一截止点核对余额、订单、账本和回调。旧订单继续路由到原处理方。
回滚先停止新接单并保全切换后的记录，禁止用旧备份覆盖新产生的财务数据。
