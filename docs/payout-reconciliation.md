# 出款退回与日终核对

候选版本 rc.12/schema 68。真实出款未启用；所有本地验收使用合成渠道响应。

## 退回款

支付宝查单经签名、付款主体、原出款单号、渠道流水和精确金额核验，整笔 `REFUND`，
或 `SUCCESS` 且 `sub_status=REFUNDED` 才能生成退回证据。有退款金额字段时必须等于原金额。
部分退回、金额缺失和身份不符进入差异处理，不自动更改余额。

原出款和结算保持成功历史；新建 `payout_return` 账本记录返还可用余额。记录、余额和审计
同事务提交，重复查询只能入账一次。如果首次查到已整笔退回，同一事务记原付款及退回，
最终释放冻结资金。渠道失败仍走原失败解冻流程。

微信当前转账产品的查单没有已验证的“成功后退回”状态，本实现不虚构该状态。银行退回
待实际银企接口规范。此类账单差异必须留存并核实渠道资金证据后处理，不能重发付款试错。

## 每日查单

`createPayoutRuntime` 组合既有出款队列与日终任务，需由受控运行环境显式注入。
应用现有启动入口没有注册真实出款运行时，收款配置不能自动开启出款。
服务启动时与随后每分钟检查上一北京时间自然日是否有核对记录；完成后当日不重复跑。
管理员可按日期重跑。中断记录标为待处理，保留每笔已完成的核对证据。

核对最近 30 天已提交单及更早尚未完成的单，仅查询原单，不发起付款。
微信单据超过官方查询保留期后，需要资金账单。不能以查询窗口代替全部历史核对。
每次最多 10000 笔，超量直接报错，不能截断后报“通过”。

`/api/merchant/epay/payouts/reconciliations`：GET 展示当前商户的记录，POST 接收
`{"day":"2026-11-06"}`。仅管理员可用，POST 需主站会话、同源和提现 CSRF token。
只有注册 `reconcile` 依赖才开放手动运行。查询失败、渠道状态不一致或在途未完成均标为问题。
报告 `scope=known_payout_queries`、`statementMatched=false`，不宣称渠道完整账单已经对平。

## 渠道账单比较

先从银行或支付平台官方后台取得原始出款/退回账单，保存到受控目录并计算 SHA-256。
按实际渠道文档转成下列格式，不上传完整卡号、姓名、手机号或密钥。接口不猜测银行 CSV 列。

```json
{
  "day": "2026-11-06",
  "channel": "alipay",
  "payer": "synthetic-payer",
  "sourceSha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "rows": [{
    "entryId": "synthetic-statement-entry",
    "outNo": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "providerId": "synthetic-transfer",
    "kind": "PAYOUT",
    "amountCents": 100,
    "occurredAt": 1793952000000
  }]
}
```

`POST /api/merchant/epay/payouts/statements` 使用同一管理员会话、同源和 CSRF 校验，
最多 1000 行/512 KiB，超量拒绝。`kind` 为 `PAYOUT` 或 `RETURN`。日期必须已结束，
行时间属于该北京时间日期，分为整数。相同原文件摘要不能导入不同内容。

逐行按渠道、付款账户、原出款单号及渠道流水匹配，记录多单、漏单、重复流水、金额差异、
未确认付款和缺失退回账本；同时检查本地该日入账记录是否缺失。以本地入账日为反向基准，
跨日迟到的渠道流水需同时核对相邻日期，保留差异说明，不能删除差异行凑平。

这属于 `operator_supplied` 人工来源比较，保留来源与标准化内容摘要、操作人和差异。
不会自动入账、修改付款状态或重发出款，也不证明上传文件就是官方完整账单。
渠道自动下载/验签、分页完整性和资金账户日余额核验须按开通产品的真实规范另行接入。

## 差异处理与恢复

1. 暂停新出款，保留查单与授权撤销回调。未知订单继续冻结，不换单重发。
2. 按原订单号取渠道结果和账单，区分尚未入账、付款失败、整笔退回及部分退回。
3. 已验证的整笔退回走事务入账；其他差异由财务核对，保留原始文件和操作记录。
4. 同时备份 SQLite、主密钥、渠道证书与配置。恢复副本后比较原表、余额、退回和审计摘要。
5. 回滚只在兼容 schema 的代码间进行；产生新出款后禁止用旧数据库快照覆盖。
